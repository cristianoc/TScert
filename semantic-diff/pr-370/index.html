Preserve facts over confined local objects across callbacks

verified

Why

A function that allocates a local cursor object, updates it through a helper whose effect writes only the cursor's scalar fields, and invokes an arbitrary-effect callback onStep(x) (such as walkVisiting in issue #355) was refused at step(xs, c) with: source expression obligation at [622,633): evidence search failed: no derivation of its node-typing claim (the callee requires safeInteger(c.i) && 0 <= c.i && c.i + 1 <= xs.length). Because onStep has the unrestricted call frame {values: any, array: any, view: any} and no separation query separates a local object's field path from the broad values class, the single pass dropped every fact over c.i across the call; diagnosis during loop-head settling also dropped framed facts before re-checking loop-head invariants.

addedSemantics local-object reachability and confinement

For any finite set P of private object and array-spine addresses, a value
or heap outside P is closed when no reachable field or array element
outside P stores an address in P. Any small-step reduction whose term
mentions no address in P and starts in a closed heap leaves every address
in P unreachable and preserves every field and spine inside P. Fresh
object, array-literal, lowered array-object, merge, and key allocations
yield addresses outside the prior heap, and writing a non-private value to
a field preserves closure.

addedCheck checked local-object confinement table

A per-node confinement table tracks which local slots hold confined objects or arrays (owned, ownedArr) and which slots may still reference them (holders). The checker requires the start node to be empty, verifies every allocation, read, write, call, and control-flow edge (requiring strict keep outside the owned arguments on calls so an outside scalar or init write cannot leak an address), and rejects any step whose unowned operand or non-inert expression could read or leak a holder. An untrusted worklist proposes a candidate table per function; only a table accepted by the checker is used.

modifiedRule single-pass call framing and loop-head diagnosis

addedTheorem confined single-pass soundness

Any function accepted by the single pass with a checked confinement table
satisfies the ordinary graph guarantee, preserving every pre-call fact over
confined locations across calls that do not mention any holder. The CLI
acceptance/soundness headline theorem and its premise are unchanged.

addedControl forged confinement proposals and scalar-write boundary

Lean controls prove that a broad scalar step can store an object value (justifying strict keep outside owned arguments) and that the confinement checker refuses forged tables with a non-empty start node, a missing holder, a framed callback mentioning a holder, a write leaking a confined object into an unowned object, or an unverified call framing a holder.

addedDocs local-object confinement design draft

Document the existing framing mechanism, the confinement extension, step-by- step trace on walkVisiting, soundness invariants, and what the design reuses versus adds in docs/drafts/local-object-confinement.md.
