Keep linear-guarded disjunctions across if merges (#367)

verified

Why

When one arm of an if updates a local variable (if (unbroken && pending >= 0) end = pending;) and the next statement exits on every run of that arm (if (!unbroken || pending >= 0) return 0;), every path continuing past the exit leaves end unchanged. Previously, the merge after the first if kept guarded facts over tag values (unbroken === true || start <= end) but dropped facts over end whose selecting condition was linear (0 <= pending), and mergeDiffs dropped predecessor facts over a live name (pending) whenever another slot (end) renamed that name to a fresh phi name.
