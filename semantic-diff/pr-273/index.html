Prove noForge of the calculus's steps at the roots of outside code

no-behaviour-change

Why

The read-only frame assumed of every step of code outside a component C that afterwards the roots of outside code reach only what they reached before or what the step allocated. With paths stepping into the code of outside closures and bound functions, this holds of every step of the calculus, so the assumption can be discharged.

addedDefinition read-only handles: good values

relative to the heap h and the roots R before a step:
Good(l) ⟺ l is reachable from R in h, or l ≥ |h|
GV(v)⟺ for every w reachable from v by code steps, every location
one location step leaves w is Good

addedTheorem what outside code holds after a step is good

h, t → h', t'C does not run activeTagc(t)h holds values
every root of t is GV
⟹ every root of t' is GV
By induction over the step: a root of t', a location's contents a
root reaches (reads, spreads, copies), a value of a root's code (a
call's run, a bound call), a substitution or instantiation of good
terms by good values, or an allocation, whose slots and cells are
fresh.

addedTheorem noForge of a step

h, t → h', t'C does not run activeTagc(t)h holds values
l reachable from roots(t') in h'
⟹ l reachable from roots(t) in h, or l ≥ |h|
A path in h' from a good value passes good locations only: a good
location's new contents are the step's roots (the stored values) or
its old contents. At a family's component this is OutsideStep.noForge.

addedExample

heap [clo, null], clo capturing {k ↦ 1}; readAt f ({f ↦ 0}) → clolocation 1 is reached before the read by f, then clo's code, then k

State that the outside-step lemmas hold whatever code runs the top segment

no-behaviour-change

Why

outsideStep_reach, outsideStep_writes and outsideStep_noForge assumed that the top segment's code is not C's, which fails for a module of C whose top level calls outside code. The assumption only fixed the roots' flag for the top segment; the lemmas beneath them hold for every top segment, its values counted as roots exactly when its code is not C's. The Lean change is in bccfdee4, swept into that commit.
