State effects as the frame condition Modifies<P, T>

Why

The stated-effects draft's written form, Within<F, T>, mixed a frame condition with postconditions: F held the two class bounds, an at map of locations and the promise members fresh, freshObject, appends and writes. A frame condition is what Dafny, Boogie and Low* call modifies, JML assignable and ACSL assigns; the promises relate the result or the changed cells to the entry heap and bound no location.

State fresh results as Fresh<T> and module cells as cell(b) keys

no-behaviour-change

Why

A fresh result written only as an @ensures atom had no form on a method, a closure or a function type in a parameter or field, where an effect's fresh promise is read. A bare key naming a module cell left bindings named values, stores or onThrow without a precise frame, and an old { value; store } payload read as cells where a module binds those names. The draft also misdescribed init and scalar, the relational promises and the citations' scope.

modifiedDocs docs/drafts/stated-effects.md, the written form

Fresh<T>, an erased result annotation composing as Modifies<P, Fresh<T>>: a normal return's array store allocated during this invocation, certified where the function is introduced, at every position Modifies takes. The @ensures atom fresh(result) is dropped. Module cells keyed "cell(b)", every binding nameable; a bare key is refused, so an old payload is invalid whatever the module binds. The reader refuses true, undefined and unknown class-map members at a location key. init and scalar as Footprints.lean defines them, each able to introduce an object reference. ReceiverGrows and ElementWrite.Holds as frames combined with relations. Beyond a modifies set: the write-permission and two-state readings, Modifies the two-state one; classes, the normal-return default with onThrow, and Fresh. O10 over every position, with subtyping and imports. The limits: effect polymorphism, relational promises in program code, the store-only region. Migration controls for old payloads with and without same-named bindings, reserved-name cells, malformed values, lookalike aliases and audited overlays; fresh controls per position.
