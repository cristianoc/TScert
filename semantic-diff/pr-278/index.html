Describe the component family a checked file lies in, on the fragment's wire

no-behaviour-change

Why

The read-only handles plan (PR 2) needs the whole component a fact relies on described before its checks (PRs 3 and 4) can read it: the laminar family of package, modules and class bodies, each one's interface, each code's innermost component, the allocation sites with their marks and keys, the possible sites of values, the typed and directed crossings, the codes that escape, the client obligation and the guarantee candidates. These are proposals: no check reads them, and acceptance is unchanged.

addedWire the fragment's components, ComponentsAst; ComponentWire.decode

components: each component's kind (package, module, class), location, span (a class's), parent (an earlier component) and interface (its entries by name, module and span, or why it is unknown); codes: each code's innermost component; sites: each allocation site's kind (object, array, closure, instance, native), keys, anyKey and its mark (local, internal, exposed, released) for each enclosing component; values: possible sites and the components a value may enter from; crossings: module, place, component, direction, position (parameter, receiver, result, argument, callResult, thrown, caught, field, binding), readOnly and value; escapes: code, component, via (result, argument, throw, store) and place; clients: each exported type's client obligation, stated or read-only, a frame over this at position 0; guarantees: each type invariant's facts of this at position 0. The decoder requires every field exactly, every index in range and each component nested as its kind is; an imported module's document is read with the empty family.

addedProposal the family, tools/components.mts

the package: the nearest package.json above the checked file in its project, where it states exports; its code the files of the builds (tsconfig*.json with outDir and rootDir) whose outputs its targets name, else every source of the project in its directory; its entries the entry modules' exports, re-exports followed. Its interface is unknown at a subpath pattern or a target no source gives. Each module of that code is a component nested in it, each class body one nested in its innermost class or module. The flow: an inclusion analysis over the family's code, insensitive to order and field names; members (entries and codes that escape) enter their parameters and receivers from outside; a call of code that may be outside a component passes its arguments out and its result in; a call of no code of the family is a native's, its result a site of its own; a read or call TypeScript types primitive holds no reference. Marks are the least the crossings (exposed at a read-only type, else released), the holds by module and captured bindings (internal) and the stores allow.
