Preserve @ensures across generic callees and stated-region module imports

verified

Why

Callers lost @ensures postconditions in two cases (issue #362): 1. Same-module generic callees: function generic<E>(c: Cursor, e: E | undefined) with @requires and @ensures safeInteger(c.i) && 0 <= c.i was lowered with no effect, dropping its @requires, @ensures, stated frame, guard and receiver, so callGeneric() was refused at use(c) while non-generic nullableResult verified. Conversely, imported generic functions from modules with a body bypassed the ordinary-import effect stripping and trusted uncertified @ensures without checking their module. 2. Imported callees with stated argument regions (such as Pretext's normalizePreparedLineStart with Modifies<{ "cursor.*": "scalar" }, boolean> and @ensures): the module's layout check matched only closed exit bounds, refusing to publish an interface entry, and the interface entry format and importer arrow reader carried only closed exits, dropping argument regions and fresh results.

Soundness

Same-module generic functions check their @ensures, stated regions and proposed footprint in their own unit (universally over all type assignments by parametricity, RequestSafe) before any caller unit can rely on them. Imported generic functions from modules with a body have uncertified effects stripped to the ordinary effect (keeping preconditions), matching ordinaryImport. Cross-module regional entries are proved sound by rowSpec_of_requestSafe and receiverDropSound using RegionalClause, ArgumentSpineRegionsWithin.of_env and exportsEstablished_frame_sound, with Verification.Tests.AxiomCheck passing and zero sorry.
