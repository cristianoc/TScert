Classify a key and an access by their meaning, not their spelling

verified

Why

Issue #119's remaining findings are decisions made on how something is written instead of what it means. A key typed 0 | 1 is a number every value of it is a number, yet the guarded-write rule demanded number among the key's clauses and refused the union; a dictionary read at number | 0 fell through a classification that knew the string union's absorption but not its numeric twin; and a host accessor was reached only through dot access, though ctx["font"] and ctx.font are one member to TypeScript.

modifiedRule the numeric key classification, runtimeNumberKey

modifiedSemantics a dictionary's read at a numeric union, keyField

modifiedLowering the named access, namedAccess

modifiedDocs SOURCE-CONTRACTS, PROGRAM-TYPING

  • index-write-guard-union positive new → verified
    // A guarded write at a key typed as a union of numeric literals, or of
// `number` with one: every value the key holds is a number, so the guard's
// mask and comparison bound it exactly as a `number` key's, and the write
// lands on an element or appends (PROGRAM-TYPING.md, "Writes at a checked
// index"). The union is the `number` key's meaning, not a different rule.
export function set(xs: number[], k: 0 | 1, v: number): void {
  if ((k & 0x7fffffff) !== k || k > xs.length) throw new RangeError("index");
  xs[k] = v;
}

// A union of `number` with a literal: the same classification, the same
// guard.
export function setWide(xs: string[], k: number | 0, v: string): void {
  if ((k & 0x7fffffff) !== k || k > xs.length) throw new RangeError("index");
  xs[k] = v;
}
  • index-read-dict-union positive new → verified
    // A dictionary's read at a numeric key typed as a union of `number` with a
// literal, or of literals alone: every value the key holds is a number,
// which names an entry, exactly as a `number` key's read — one meaning, one
// decision.
export function lookup(
  table: { [key: number]: string },
  key: number | 0,
): string | undefined {
  return table[key];
}

export function lookupLiteral(
  table: { [key: number]: string },
  key: 0 | 1,
): string | undefined {
  return table[key];
}
  • dom-canvas-context-bracket positive new → verified
    // A 2D context's host accessors read and written through bracket access at
// a string key: TypeScript gives `context["font"]` and `context.font` one
// meaning, so each is the accessor's intrinsic, exactly as the dot spelling
// (SOURCE-CONTRACTS.md, the overlay of library types).
type Context = CanvasRenderingContext2D | OffscreenCanvasRenderingContext2D;

export function measureIn(
  context: Context,
  font: string,
  text: string,
): number {
  context["font"] = font;
  return context.measureText(text).width;
}

export function readsFont(context: Context): string {
  return context["font"];
}

export function setsKerning(context: Context): void {
  context["fontKerning"] = "none";
}
