Why

Since pretext's walkPreparedComplexLines (line-break.ts, 9,917 program nodes, 325 loop heads) reaches proof search, its search takes 152 s CPU, and each file importing it searches it again as a module run: the first searches of line-break.ts, layout.ts and rich-inline.ts take 153 s, 173 s and 182 s CPU, past the 60 s stage limit. The search fails, so it runs all six of its rounds over every node. Profiling (macOS sample) put 74% of the time in list membership tests: each pass over the nodes, at each node still waiting for a predecessor, tested the 325-element cut list and the handler-target list and looked the node up in the requirement and seed lists, and a waiting round makes 4,781 passes. The rest went largely to reading a point's claim, and an edge's source slot, by position in a list.
