Add the paper "Effect languages"

no-behaviour-change

Why

A walker that calls a visitor keeps no fact about a value location across the visit. The visitor's type states one closed effect, and the only regions it can use for what a closure writes through its captures are class regions. So walk below is refused at xs[c.i]: the entry values: any covers the walker's own cursor field c.i, which the visitor cannot reach. Pull request 338 infers what the visitor must preserve. This paper writes it down instead, in a richer effect language, and checks it with the existing rules.

addedDocs paper: effect languages

An effect language supplies regions, their meaning, a substitution of paths for roots, and sound decisions of inclusion, disjointness and rigidity (properties E1–E4). The general rules (Sub, Frame, Seq-Eff, If-Eff, Loop-Eff, Call, Fun, Fresh-Eff) are stated over any such language; their soundness at that generality is a conjecture. The specific rules give the effects of the steps in one language's regions. L₀ is the language TScert has: the regions of Footprints.Region, with the general rules and the specific rules, each with the Lean name that proves it; the annotations state a part of it. L₁ is proposed: regions rooted at a closure's captures, effect variables, anchored effects, reach through declared keys, constraints ε ◁ S in quantified signatures, and named regions, with three rules specific to them (Var-Resp, Fresh-Anch, Inst). The paper derives Pretext's line-walker patterns W1–W6 in L₁ and states its limits. L₁ has no implementation and no proof.

Example

type Visitor = (i: number) => Modifies<{ values: "any"; spines: "grow" }, void>;export function walk(xs: number[], visit: Visitor): number {  const c = { i: 0 };  let sum = 0;  /** @invariant safeInteger(c.i) && 0 <= c.i */  while (c.i < xs.length) { visit(c.i); sum += xs[c.i]!; c.i++; }  return sum;}
