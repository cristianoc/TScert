Build the Lean library and the verifier with Lean v4.37.0-rc1

no-behaviour-change

Why

Lean v4.37.0-rc1 builds the library 25% faster than v4.33.1 (wall time of a clean build, measured below). Under it, with warnings as errors, the sources at v4.33.1 fail in five ways: deprecated core names; the new contract clauses of def (given, requires, ensures, throws), whose words a declaration's binders and type may no longer hold bare; withPtrEq, which the compiler now refuses at a type variable; simp and environment API changes; and a new instance, UInt64.instDecidableForall, that decides ∀ x : UInt64 by enumerating 2^64 values and is chosen over the list instance for ∀ b ∈ S, b ∈ T with S : List UInt64. That last one made the verifier's check of two numIn clauses run past the 60 s stage limit (blocker-callback-array-index: 1.25 s under v4.33.1, over 180 s).

modifiedTooling Lean toolchain

modifiedTooling deprecated names, each by the replacement Lean names

modifiedTooling identifiers named given, requires, ensures, throws

addedDefinition sameObjectOr a b k h

sameObjectOr a b k h = k ()
The compiled verifier runs withPtrEqUnsafe: true where a and b are
one object, else k (). It is the definition v4.33.1 gave withPtrEq,
used where the value's type is a type variable (decideSame, same,
memFast, withinFast, subB); withPtrEq stays where the type is known.

modifiedCheck the decision of CoversWith

modifiedTooling axiom checks

Effect

  • every pipeline case positive and negative unchanged 3502 of 3503 as expected under both toolchains; invalid-guard-constant-across-loops fails the same way under v4.33.1

Soundness

No theorem changes its statement: renamed lemmas state what they replace, escaped identifiers are the same names, and the proofs read sameObjectOr's definition, k (). The decided proposition of CoversWith is unchanged; only its decision procedure is chosen.
