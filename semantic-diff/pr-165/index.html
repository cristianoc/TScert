Describe the typed array as a primitive in the note

no-behaviour-change

Why

The note said how a write through a typed array changes the heap in one sentence about worlds in posts, with no assertion form, rule or example using it. A typed array is a primitive of the language: its own storage and its own steps, like an array. The note states them, and the write's frame becomes an ordinary effect on one more class region.

addedDefinition drafts/tolerant-frames-note/note.tex, section 2

The typed array: an object with a fixed element format and a view
store of form viewN, of fixed length N, without holes, listing
cells that hold numbers of the format; created by library calls;
distinct typed arrays have distinct view stores and may share
bytes. Its three steps in Definition "Commands": read, write,
length. A sixth atom, the element of a typed array at an index.

addedDefinition drafts/tolerant-frames-note/note.tex, "Regions"

The class region all-views, the view stores, a subset of
all-stores. Value locations, array stores and view stores partition
a heap's locations; class regions read the kinds and forms the
world records, are rigid and rebase to themselves; an ordinary
array's store is disjoint from all-views.

addedRule drafts/tolerant-frames-note/note.tex, section "Programs"

View-Length, View-Read, View-Write. The write has effect
{all-views: grow} and the post: the written index reads the
converted value and every other index of the same typed array reads
what it read. Marked a conjecture; the Lean states the frame as the
post ViewWrite of a native call.

addedExample

Across `b[0] = 7`: a length bound and a quantified fact of anordinary array, a field's value, another typed array's length andanother element of `b` hold; an element of another typed array mayfail, with the two typed arrays that make it fail.
