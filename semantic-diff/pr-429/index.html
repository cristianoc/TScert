Unwrap clause type aliases, lower read-link bounds at merges, and hoist SinglePass queries

verified

Why

Clauses on functions taking or returning a non-record type alias (such as type NumList = Dense<number[]>, type Bytes = Uint8Array, or type Idx = SafeInt) were refused when checking field kinds in the parser's clause validator, because clauseParameter read the alias reference without expanding it. Separately, after Store.add began lowering field-path linear facts through read links (Store.lowerAtom), a branch merge where one arm assigns o.f = localVar (leaving 0 <= localVar lowered behind o.f ↦ localVar) and the other assigns o.f = expr lost 0 <= o.f and o.f <= MAX_SAFE_INTEGER because mergeEntailed neither proposed read-link restated candidates nor lowered candidates through each view's read links. Finally, verifying large functions spent significant time rebuilding per-state separation queries and linear contexts inside per-atom filter loops, emitting bitmask side atoms for unused masks, and scanning all linear facts when collecting bitmask hypotheses in restateAddedAtIndex.
