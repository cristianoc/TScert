Admit Uint8Array, Uint16Array and Int32Array as views of bytes, with writes

verified

Why

Pretext (chenglou/pretext at 0d102a5c) keeps its tables and flags in typed arrays. A file naming Uint16Array or Int32Array was refused with "type outside the fragment (ThisType) in lib.es5.d.ts#Uint16Array": the standard library declares their methods with the polymorphic this type, which TScert's types do not have. new Uint8Array(n) and the other two constructors were refused as globals no reviewed entry admits, and a write flags[i] = 1 was refused as a key the view's type does not state. Uint8Array as a type was admitted already, through the overlay of library types: a host object whose elements and length are read through %ByteAt% and %ByteLength%. The census of pretext's src/ names these refusals for 82 of its 209 functions.

modifiedTrust overlay of library types: views of bytes

addedLowering parser: an element write of a view of bytes

b[k] = v
⇝%ByteSet%(b, k, v)
(TypeScript types b as views of bytes only and k as a number)
%ByteSet% : (Uint8Array, number, number) ⇒∅ number

addedTrust library globals: typed array constructors

new Uint8Array / new Uint16Array / new Int32Array : (number | readonly number[]) ⇒∅ Uint8Array a length converted by ToIndex, or an array stepped by the untampered array iterator and each element converted by ToNumber: no code runs, and only the fresh view is written. The globals are only constructed

addedRefusal unstated members of a view

map, filter, slice, every and the other members that call a callback or a species constructor find no member; new Uint8Array(v) of a view, b[k] += v and b[k]++ are refused

    // The standard library's `Uint8Array`, `Uint16Array` and `Int32Array`, as
// pretext uses them (chenglou/pretext at 0d102a5c, src/): record fields and
// parameters, construction at a length and from an array of numbers,
// element reads and writes at a number, `length`, and the methods `fill`,
// `copyWithin`, `set` and `subarray`.
export type Runs = {
  index: Uint16Array;
  values: Uint8Array;
  ends: Int32Array | null;
};

export function unpack(blocks: number): Runs {
  const index = new Uint16Array(0x100);
  const values = new Uint8Array(blocks << 8);
  const whole = new Int32Array(0x100).fill(-1);
  for (let i = 0; i < index.length; i++) index[i] = i;
  values.fill(1, 0, 8);
  values.copyWithin(8, 0, 8);
  index.set(new Uint16Array([1, 2, 3]), 1);
  return { index, values, ends: whole.subarray(0, 4) };
}

export function mark(len: number, at: number): Uint8Array | null {
  let leftOut: Uint8Array | null = null;
  if (at < len) (leftOut ??= new Uint8Array(len))[at] = 1;
  return leftOut;
}

export function first(runs: Runs): number {
  const ends = runs.ends;
  const end = ends === null ? undefined : ends[0];
  return (runs.values[0] ?? 0) + (runs.index[1] ?? 0) + (end ?? 0);
}

  • node-bytes-write positive refused → verified a write of 300 reads back 44, a number
    // A write through a view of bytes at a number is `%ByteSet%`'s: it converts
// its value by ToNumber, which runs no code on a number, and keeps it modulo
// 256 (run under Node: 300 reads back as 44). The element read back is a
// number, or `undefined` past the end.
export function write(bytes: Buffer, value: number): number {
  bytes[0] = value;
  return bytes[0] ?? -1;
}

Soundness

The model holds no element of a view, so %ByteSet% and the methods change no location the model holds; %ByteAt% still answers a number or undefined after any write. Each stated member was audited against ECMA-262 and Node's Buffer.prototype, and run under Node 26.13.0.
