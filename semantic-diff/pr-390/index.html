Prove guarded element-length and parallel-array invariants in SinglePass

verified

Why

Quantified clauses over arrays of nullable nested arrays (such as forall i in a: a[i] === null || 1 <= a[i].length and b === null || forall i in a: a[i] === null || b[i] === null || a[i].length <= b[i].length) could not be stated or discharged in the proved SinglePass verifier because: - quantified clauses (Fact.every) supported only bare linear/disjunctive bodies over a single array, not element nullability guards or parallel reads of a second array at the same index; - optional-property links were lowered as non-optional at loop heads, dropping guarded invariants on optional object properties across loop back-edges; - bare-slot guarded facts stayed locked when branch narrowing refined the slot's type in Γ (e.g. extras === null ? ... : extras[g]!) without recording a ValueSet fact; - nearStep collected guarded and disjunctive facts into linearNear's 40-fact budget before reaching linear bounds at large loop merges; - guarded field reads (x === null || ...) and element spines needed footprint survival and merge-point tracking across nullable guards and effect-bounded callbacks.

modifiedDefinition semantics: quantified body clauses, parallel targets, element-spine region

addedRule SinglePass: guarded element instantiation, type-directed guard release, and guarded merges

- From forall i in a: (a[i] === t || ...) (or parallel b[i] === t || ...),
instantiating at an element binding x = a[i] (or a?.[i] ?? null /
a[i] ?? null / ternary) yields a guarded fact on x (and parallel y = b[i]),
released once x (and y) is narrowed away from tag t.
- From Γ[s] excluding tag t (checked via HeapKnowledge.typeExcludes,
proved sound from answers_sound), unconditional bare-slot guarded facts

- At control-flow joins, mergeGuarded preserves nested guarded facts,

guarded clauses through indicesFilter.
- nearStep filters linearNear to linear/int/length/index/bound facts
(nearRelevant) so guarded/disjunctive facts do not crowd out linear
bounds at loop merges.
- Region.elemSpines support and survival rules prove guarded element-length
and parallel-array quantified facts survive spine-preserving steps and
disjoint writes, including element-spine framing in EffectLanguage/Model.

modifiedLowering loop-head read links and head inference for coalesced element reads

Restrict quantified array-spine framing to array spines and support confined element writes

verified

Why

Two framing limitations prevented quantified invariants on ordinary arrays from surviving loops that mutate typed arrays or multiple locally allocated arrays: - Region.elemSpines was bounded as KindSet.spines (arrays and typed-array views together), and everyCells / parallelCells used Region.spine even when the array path's type or length term established an ordinary JS array. As a result, a Uint8Array byte write (whose frame modifies only view spines) invalidated quantified element-length and parallel-array invariants on ordinary arrays. - LocalConfinement did not recognize element writes (a[i] = v) on confined locally allocated arrays, and its greedy post-pass over escaping allocations scored only framed call counts rather than prioritizing outside nodes (mutations whose effects stay inside the confined set so every caller-reachable parameter outside the set is framed). In addition, HeadInference.Fact.keptAcross dropped quantified facts at loop heads on any .elemWrite or .indexWrite rather than letting the pass check them.

modifiedDefinition semantics: array-spine precision for elemSpines, everyCells, and parallelCells

addedRule SinglePass: confined array element writes and outside-first confinement proposal

- LocalConfinement recognizes element writes on confined owned arrays
(isConfArrElemWrite), proving in elemWriteKeep_sound that they keep
all locations outside the confined set and therefore qualify as
outsideNodes in checkNode and nodePostNCore.
- LocalConfinement.propose scores candidate escaping allocations
lexicographically by (outside.length, framed.length) so multi-array
confined loops frame outside parameter invariants.
- HeadInference.Fact.keptAcross retains .every proposals across
.elemWrite and .indexWrite for the pass to verify or refuse.

Match quantified guards to their field paths and record the closed write gap

verified

Why

For a row with nullable left and right fields, testing left against null let elaboration resolve right.length. With left equal to [] and right equal to null, reading the length throws under Node. The Pretext tier also recorded a confined field-write pattern as a gap although both functions in the case verify.

    // Bounds pattern P3: a quantified fact across a write outside its array.
// Fact: forall i in items: 0 <= items[i] < widths.length, kept across
// `fragment.width = s`, a write of a field of a fresh object, whose location
// is no element of `items` and no spine of `widths`.
// Pretext: rich-inline.ts createLine (12 sites), setEmptyObjectFacts (7).
type Fragment = { item: number; width: number };

/** @requires forall i in items: safeInteger(items[i]) && 0 <= items[i] && items[i] < widths.length */
export function acrossWrite(items: Int32Array, widths: number[]): number {
  const fragment: Fragment = { item: 0, width: 0 };
  let s = 0;
  for (let i = 0; i < items.length; i++) {
    fragment.width = s;
    s += widths[items[i]!]!;
  }
  return s + fragment.width;
}

/** @requires forall i in items: safeInteger(items[i]) && 0 <= items[i] && items[i] < widths.length */
export function acrossWriteInvariant(items: Int32Array, widths: number[]): number {
  const fragment: Fragment = { item: 0, width: 0 };
  let s = 0;
  /** @invariant safeInteger(i) && 0 <= i
   * @invariant forall k in items: safeInteger(items[k]) && 0 <= items[k] && items[k] < widths.length */

  }
