Replay a group's verdict when its slice is unchanged

no-behaviour-change

Why

A file worker's pieces were keyed by the whole Fragment, so any edit to a file, a comment included, executed every group again: walking pretext forward through upstream's four commits re-ran every group of every file each commit touched.

addedDefinition the stage store: a group's piece

key(group) = SHA256(canonical({operation, implementation, slice}))
operation= check-slice | propose-slice
implementation = the adapter, the executable and its libraries, the
runner, the runtime and the stage environment
slice= SHA256 of the group's position-relative slice, its
callees' proposal answers included
On a changed file the worker prepares once and resolves the groups in
callee order; a group whose key the store holds takes the stored
verdict and proposals, rendered at the current positions, without
planning or checking; a miss checks the slice and publishes its
verdict and proposals atomically. A file whose worker identity is
unchanged starts no worker.

modifiedDefinition the verifier's CLI: a slice's positions

addedControl the stage store: forged group pieces

A piece with a wrong operation, a mismatched member, a bad payload digest or a stale occurrence map is not replayed, and a worker killed during publication publishes nothing partial.
