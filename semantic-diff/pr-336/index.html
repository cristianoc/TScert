Add support-parametric callback demands to single pass and PassUnit

verified

Why

Internal higher-order walkers iterate over arrays (directly or through nested record paths such as prepared.widths and prepared.segmentFlags) while invoking an unannotated callback. Callers pass closures that accumulate into fresh local arrays, or wrap the walker in an adapting closure (walkLines). Without support-parametric callback demands, the single pass either drops heap facts across the callback call or depends on ReadOnly client trust (Θ_C) and explicit handle wrappers that do not cover nested paths or adapting closures.

addedDefinition calculus: callback support demand

SupportedAt(F, ρ, h, h') ⟺ ∀ fp ∈ F, Supported(fp, ρ, h, h')
where F is a list of footprints (keep or grow on a parameter-rooted
region), ρ is the frame, h is the pre-call heap, and h' is the
post-call heap. A CallbackDemand(k, F) pairs callback parameter slot k
with the footprints F that every call to parameter k must preserve.

addedTheorem calculus: path-provenance freshness and confinement

HeapOk(h) ∧ RootsOk(ρ, h) ∧ l ∈ region(r, ρ, h) ⟹ l < h.length
Every footprint region evaluated before a callback call selects only
pre-existing heap locations (< h.length). Consequently, mutations
restricted to freshly allocated locations (≥ h.length) preserve every
parameter-rooted region (direct fields, nested paths, spines, and
cells) without enumerating region shapes. Multi-step transitivity
composes demands across adapting closures.

Every accepted callback-demand plan establishes ordinary graph safety

  • callback-demand-walk positive new → verified local cursor + fresh local accumulator, zero Θ_C
    // Support-parametric callback demand: mutable array + local cursor.
// `walk` keeps `c.i` by local confinement and publishes a callback demand
// on `visit` preserving `xs`'s spine (`grow`). `sumAndTrace` discharges the
// demand because `visited` is allocated fresh (apart from `xs`).
type Visitor = (i: number) => void;
type Cursor = { i: number };

function walk(xs: number[], visit: Visitor): number {
  const c: Cursor = { i: 0 };
  let sum = 0;
  /** @invariant safeInteger(c.i) && 0 <= c.i */
  while (c.i < xs.length) {
    visit(c.i);
    sum += xs[c.i]!;
    c.i++;
  }
  return sum;
}

export function sumAndTrace(xs: number[]): number {
  const visited: number[] = [];
  return walk(xs, (i) => {
    visited.push(i);
  });
}

  • callback-demand-nested-path positive new → verified nested path walkRaw + collectDirect via path-provenance freshness
    // Support-parametric callback demand on nested record paths (`collectDirect`):
// `walkRaw` preserves `prepared.widths.length === prepared.segmentFlags.length`
// across `onEntry` and publishes a path-level demand on `prepared.widths` and
// `prepared.segmentFlags`. `collectDirect` mutates freshly allocated `walked`,
// separated from all pre-existing paths of `prepared` by path provenance.
export interface PreparedData {
  widths: number[];
  segmentFlags: number[];
}

type Cursor = { i: number };

/** @requires prepared.widths.length === prepared.segmentFlags.length */
function walkRaw(
  prepared: PreparedData,
  onEntry: (width: number, flag: number) => void,
): void {
  const c: Cursor = { i: 0 };
  /** @invariant safeInteger(c.i) && 0 <= c.i && prepared.widths.length === prepared.segmentFlags.length */
  while (c.i < prepared.widths.length) {
    const w = prepared.widths[c.i]!;
    const f = prepared.segmentFlags[c.i]!;
    onEntry(w, f);
    c.i++;
  }
}

/** @requires prepared.widths.length === prepared.segmentFlags.length */
export function collectDirect(prepared: PreparedData): number[] {
  const walked: number[] = [];
  walkRaw(prepared, (w, _f) => {
    walked.push(w);
  });
  return walked;
}
