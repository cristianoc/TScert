Extend front end for merged interface+value imports, mapped intersections, and const tuple followers

verified

Why

Three TypeScript front-end patterns in SkipLabs/skip main were refused before reaching Lean: 1. Merged interface + companion const/function declarations (such as export interface ServiceInstance + export declare const ServiceInstance) failed import resolution, contextual type lookup, and written-application sweeps with TypeScript found 2 declarations. 2. Computed generic type aliases whose body is an intersection containing a homomorphic mapped type (such as AllInputDefs<T> / AllSharedCollections<T> intersecting with { readonly [Symbol.iterator]?: never }) were not classified by computedAlias, causing generic reading to fail before concrete call-site instantiation. 3. Call-site instantiation of const tuple type parameters in intersection parameter types (such as asFollower's const Eager extends readonly EagerKeys<ResourceInputs>[]) failed to extract Eager across the intersection, crashed on empty tuple elementFlags, and lacked sound TypeTerm-level evaluation for mapped-index conditionals over keyof T & string, bare nominal reference conditionals, tuple-wrapped [X] extends [never] guards, literal/primitive Exclude, and literal-key-union transforming mapped types (FollowerLazies).

Name the front end's type rules, make two follow TypeScript, and state them as trust

verified

Why

The type reductions the front end applies itself had no names and no stated meaning, and two of them disagreed with TypeScript, giving wrong acceptances: { [K in keyof X & string]: X[K] } kept a field 0 and kept X's modifiers, and { [P in L]: P } gave a number key the string as its value.

modifiedDefinition the front end: rule mapped-keyof-string

modifiedDefinition the front end: rule mapped-literal-keys

addedDefinition the front end: rules conditional-tuple-never, conditional-literal, conditional-nominal, index-string-fields, intersection-alias

Each rule is named where it is applied and in its refusals, and stated
in SOURCE-CONTRACTS.md, "Front-end type rules".

Effect

  • mapped-keyof-string positive positive new → verified optional field required, readonly writable, string index absorbs fields
    // Rule mapped-keyof-string: `{ [K in keyof X & string]: X[K] }` is not
// homomorphic in TypeScript. A field optional in X is required, holding
// undefined; a readonly field is writable; a string index absorbs the fields.
type KS<X> = { [K in keyof X & string]: X[K] };

export function optionalBecomesRequired(): KS<{ a?: number }> {
  return { a: undefined };
}

export function readonlyBecomesWritable(o: KS<{ readonly a: number }>): number {
  o.a = 2;
  return o.a;
}

export function indexAbsorbsFields(): KS<{ [k: string]: number; a: number }> {
  return {};
}
  • invalid-mapped-keyof-string-optional negative negative new → refused the empty object lacks the required field
    // Rule mapped-keyof-string: the field `a`, optional in X, is required in
// `KS<X>`; TypeScript rejects the empty object.
type KS<X> = { [K in keyof X & string]: X[K] };

export function missingRequired(): KS<{ a?: number }> {
  // @ts-expect-error Property 'a' is missing
  return {};
}
  • invalid-mapped-keyof-string-numeric negative negative new → refused a key that reads as a number is refused
    // Rule mapped-keyof-string: `keyof X & string` drops the number key `0`, so
// TypeScript rejects a value with a field `0`. The front end holds `0` and
// `"0"` alike and refuses the key.
type KS<X> = { [K in keyof X & string]: X[K] };

export function extraNumericKey(): KS<{ 0: string; a: number }> {
  // @ts-expect-error '0' does not exist in type
  return { a: 1, 0: "x" };
}

    // Rule mapped-keyof-string refuses a key that reads as a number: TypeScript
// accepts this program, keeping `a` and dropping the number key `0`.

export function make(): KS<{ 0: string; a: number }> {
  return { a: 1 };
}
