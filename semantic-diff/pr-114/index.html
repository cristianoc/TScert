Draft the rule for array writes at a run-time index, with what each pretext site relies on

no-behaviour-change

Why

Pretext's original index writes xs[k] = v (k a computed number) are refused, so pretext rewrites 56 of them as splice(k, 1, v) and one length cut as splice(n), and those rewrites cost run time in every engine measured. At pretext 18360b74, the minimal rewrite set with the writes turned back, each of the 12 refused functions is refused at a write: "a numeric array key needs a proved array-index singleton". No rule types a write whose key is known only as number, and none can without a fact about the key: at an index past the length the write leaves holes a number[] does not admit, and at a numeric key that is no index it writes an own property whose location another reference may hold at a narrower type.

addedDocs docs/drafts/index-writes.md

The write is typed where a checked fact gives the key a valid array index at most the length, in the state after the right side: setElem-bounded, with a same-value write and a length cut beside it. Every one of the 57 sites is listed with the fact it relies on: a present read on an array whose own keys are its store and prototype (presence), the function's own integer arithmetic (#104's numeric facts), a caller's or callee's fact (#104's decision P), or a relation between two structures. Presence accepts 2 of the 12 functions, presence and numeric facts 3; the other 9 hold a site needing a caller, callee or cross-structure fact.

modifiedDocs WORK.md row

A row for the draft, awaiting the owner's choice of route.

Gap

No rule is implemented: each route needs #104's fact language, and the route and #104's decisions N and P are the owner's.

Soundness

Astra reviewed the draft (pass with changes); the changes are in this version: an explicit valid-index premise, presence only on a clean array or with an index fact, operands bound before the store is read, the 2^32-1 edge, and the corrected site kinds.
