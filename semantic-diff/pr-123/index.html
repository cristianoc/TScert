Give a condition's answer its execution plan excludes the unreachable state in the producer

verified

Why

if (true || flag) { picked = seed; } followed by scaled(picked), with let picked: number, was refused: "No rule derives this invoke at number from picked: undefined | number". The producer's condition computes, along the condition's evaluation plan, the state where it holds and where it fails, None for an answer no path reaches. For such an answer it fell back to the syntactic refinement of the whole condition, a state some values meet, so the join after the if took in the entry state where picked is still undefined. The statement flow worked around this for one form only, a branch whose test is the literal true or false (the head of do and for (;;)), and kept its own copy of the unreachable state.

Gap

a condition whose answer is decided only by its value, not by its plan, keeps both answers: if (true === true) (an equality's result is not a constant of the plan) is refused as the true || flag form was, and a conditional expression's value (true ? seed : undefined) is typed as the union of both arms

Soundness

the producer's states only propose claims. An edge no run takes is accepted by vacuous-edge, whose premise is the edge source's context in Lean (the tested value refined by the answer it rules out, a call's result at the empty type), whatever the target's claims state; every other edge into a join still establishes the join's claims. A cell's contents are emptied as well because the producer's join recognises an unreachable state by a binding at the empty type, which for a cell is its contents: a state of cells alone, contents kept, would join the cells' entry contents into what follows (observed with a module let holding number | undefined, read after a while (true) loop: the read was proposed at undefined | number | 1). No Lean rule or check changes.
