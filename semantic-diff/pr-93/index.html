Admit Float64Array as a view and Intl.Segmenter with its segments, as pretext uses them

verified

Why

Pretext (chenglou/pretext at 0d102a5c) keeps a kerning table in a Float64Array and splits text into words with Intl.Segmenter. A file naming Float64Array was refused with "type outside the fragment (ThisType) in lib.es5.d.ts#Float64Array", and new Float64Array(n) as a global no reviewed entry admits; .fill(NaN) then met the global NaN, also unreviewed. Intl.Segmenter in a signature was refused with "a qualified type reference in getWordSegmenter": only a namespace import's member was read qualified. new Intl.Segmenter(…) was refused because the namespace Intl was read only by calling its functions. The census of pretext's src/ named these refusals for 64 of its 209 functions.

export type Measurement = {
  kanaKerning: Float64Array | null | undefined;
  size: number;
};

export function getKerning(
  measurement: Measurement,
  count: number,
): Float64Array | null {
  if (measurement.kanaKerning === undefined) {
    measurement.kanaKerning = null;
    if (count > 0)
      measurement.kanaKerning = new Float64Array(count * count).fill(NaN);
  }
  return measurement.kanaKerning;
}

Soundness

The model holds no element of a view and no slot of a segmenter, its segments or their iterator, so the stated members and the iteration step change no location the model holds. Each stated step was audited against ECMA-262's TypedArray objects and ECMA-402's Segmenter objects, and each negative case run under Node 26.13.0.
