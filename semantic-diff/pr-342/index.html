Why

Check closures calling a marked input by Adapt and fresh arrays by FreshRead

refused

Why

walkVia, which passes walk the closure i => visit(i), published no interface: the closure's call of the unknown visit has the unrestricted effect, and Use refused it. traceField, which walks h.xs and pushes onto a fresh array, was refused: the value read from h.xs has no separation facts. The note's walkLines failed the same way as walkVia.

modifiedDocs inferred callback preservation note

Adapt states the exceptional support it forwards and the value restriction in path-closure; the examples carry their regression status; aliasedRead is the refused program with its Node result; the correspondence table names the definitions.

Example

export function aliasedRead(h: { xs: number[] }): number {  const visited: number[] = [1];  h.xs = visited;  return walk(h.xs, () => { visited.pop(); });}

Counterexample

aliasedRead({ xs: [] }) under Node returns NaN: the walked array isthe one the callback pops, and xs[c.i]! reads undefined. FreshReadadds no fact, since the write exposes visited before the read.

Gap

collectDirect and collectAdapted stay refused: a fresh array against a demand on a path from an input needs the note's second conjecture.

Soundness

Both rules are experimental: their verdicts are refusals that name the experimental check, never verified verdicts. The soundness of Adapt and the exposure invariant of FreshRead are stated in the note, not in Lean. The verified worker's checks and theorems are unchanged.
