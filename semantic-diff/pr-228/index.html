Why

pretext's prepareRichInline@8562 (src/rich-inline.ts) was refused from 100c896a on: "edge from node 1150 into node 833: its assertion lacks [cell 13.lineEndTrims]". Inside if (sub.lineEndTrims !== null) the source calls zeroList, which pushes to a module array. Its inferred frame, built from push's frame {receiver spine: grow}, is {values: keep, arrays: grow, views: keep}; under push's earlier class-wide frame {value: any, spine: grow} it changed values. The type computation ends a field's narrowing only at a call whose frame changes a value location, so it kept sub.lineEndTrims non-null past the call and stated it at the next statement. The pass's call step kept no cell fact across an ordinary call: only a call within the empty frame, one changing its receiver's own fields, a stable member's read and push's postconditions kept one. The fact the type computation stated was not established on the edge from the call, and the unit was refused.

Γ; Σ ⊢ r ← t ⊣ …, y.f ∈ V

Φ is the call's normal frame at the caller's slots; y.f # r is the
knowledge's separation query answering that the field y.f and the
region r share no location. The support of y.f ∈ V is the location
y.f at a change into V; an entry respects it where it keeps its
locations, where it holds only spines and changes them otherwise than
arbitrarily (a spine stays a spine, and every spine meets V alike), or
where it is apart from y.f.
