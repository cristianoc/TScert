TScert · its own front end

Where proofs of TScert’s own code fail

TScert checks type claims about TypeScript programs. Its complete tools/ census verifies 489 of 679 functions: 72.0%. This deck explains what that counts, how the first refusal of each remaining function sets priorities, and what the measured round establishes. A failed proof search does not by itself show an unsafe program.

changed

How to read the evidence

A verified function and a small case answer different questions

A verified function

The parser reads source and annotations. A producer proposes type claims; proof search tries to justify them; an independent checker validates the evidence. A function verifies when its complete slice succeeds. A slice includes the function’s dependencies, which can contain its first refusal.

The safety boundary

The checker’s type-safety result is proved in Lean, a proof assistant. Its application to TypeScript also relies on faithful source translation and audited external contracts. A contract states the results and effects assumed of code outside the checked source.

A pipeline case

A small source has an expected outcome in pipeline/cases.mts. A positive case verifies. A negative case is refused and demonstrates unsafe behavior. A gap case records a missing capability. Success of one small source establishes that obligation; a larger caller can meet a further refusal.

Cited rule · dev/census.mts; inspected saved source sites

Rank the first observed construct, not a generic error message

  • One function, one first refusal: read its saved slice at the recorded source span. All saved slice hashes match the census. Shared recursive text still represents each named function separately. Later refusals are outside this ranking.
  • One construct per group: split generic search failures using their source expressions and input contracts. The tables name observed constructs, not proved causal defects. A missing source location stays an unlocated obligation; it is not assigned an invented cause.
  • The priority weight: a function with n statements contributes 10 / (10 + n). A 10-statement function contributes 0.5; a 90-statement one, 0.1. Add contributions for a group and sort by the full value. Tables round to three decimals. Smaller functions often have fewer later refusals.
  • An existing host boundary: a small wrapper performs an external operation outside the model. Callers use its audited contract; its implementation remains refused. Rows 7, 14 and 19 are documented examples, whose implementation refusals alone call for no new language support.
  • Choosing work: weights rank observed refusals. Choose further cases after checking which routes already answer or restrict them. Counts describe blocked code, not promised gains; all 190 functions and their 10,228 statements contribute once.

Cited source contracts and executable cases

Retain known contracts, then check their definitions

Compiler identity is JSON data

blocker-round-compiler-identity-json verifies with the constructor’s full field union and its JSON-data bound. The actual current function reaches the later result-record obligation in group 4. JSON-safe data must account for every field; an assertion of a convenient shape cannot establish it.

Owned matcher preservation

blocker-round-global-signature-matcher verifies. Its string-comparing matcher preserves existing array storage on normal return, including lengths and which indices are present. globalEntry verifies in this census. A matcher using pop shortens the array and violates that guarantee; the falsely promised version is refused and throws TypeError under Node.

A semantic binder printer

blocker-round-binder-entries verifies using the shared complete type-term printer before serialization. The larger mergeRefusal function reaches the scope-object obligation in group 13. The source repair compares semantic fields, retaining declaration-identity spans.

  • Use the whole contract: a footprint describes allowed value and store changes. A qualified callback must establish it from its body. A normal-return guarantee supplies no preservation when the call throws. The existing effect checks and negative cases guard that boundary.

Cited policy · docs/SOURCE-REWRITES.md

Choose the first route that establishes the obligation at acceptable cost

RouteRequired evidence
SupportA checked rule or audited external contract admits the construct
Runtime checkAn executable check establishes the complete required property
RepairThe source corrects a defect exposed by the refusal
AvoidanceAn equivalent source form preserves returns, exceptions and effects
Host boundaryA small wrapper performs an external service operation; callers assume its audited contract
Trusted unitThe owner accepts a local unit’s complete contract as an assumption
ProofA Lean proof establishes the required fact in the model
  • First inspect whether the source discards information its own construction already establishes. A negative case needs demonstrated unsafe behavior. A refused ordinary program remains an obligation to investigate, even when another source form verifies. The status table in WORK.md owns each investigation’s status.
