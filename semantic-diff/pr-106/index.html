Read a closure's contextual result from one callable type alone, not an optional one

verified

Why

Reading undefined | V as V for a closure literal's contextual result too made p.finally(() => ({ then(…) {…} })) claim its object at void's unknown result, which proposed the literal's then at primitive types and refused it there: invalid-finally-thenable failed at that allocation, before the thenable obligation it controls. The visitor case needs the optional context only for the signatures it offers.

    // A `finally` callback returning an object whose `then` is callable: the
// native `finally` resolves the cleanup result before forwarding, calling
// that `then` (run under Node: `log` holds 1 once the result settles).
export function cleanup(p: Promise<number>, log: number[]): Promise<number> {
  return p.finally(() => ({
    then(resolve: () => void): void {
      log.push(1);
      resolve();
    },
  }));
}
