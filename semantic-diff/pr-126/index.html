Read a parenthesized expression at the decision that spelled it directly

Why

TypeScript gives a wrapped and an unwritten expression one meaning, but two decisions compared node shapes instead: the fresh-array fill rule demanded the construct written directly as fill's receiver, and a parameter's literal default was read at the initializer node itself. Both refused spellings TypeScript reads the same (#119, findings 4 and 5), so a program a reviewer reads as the reviewed form was refused for how it was written, not what it means.

modifiedLowering the filling read, fillCall and literalDefaultName

Effect

  • array-fill-parenthesized gap unsupported → verified
    // Parentheses around `new Array<T>(n)` before its `.fill(v)` are transparent:
// TypeScript gives the wrapped and the direct form one meaning, so the
// construct is read as `fill`'s receiver and the call as the filling
// intrinsic, exactly as written directly
// (SOURCE-CONTRACTS.md, "`new Array` filled at once").
export function zeros(n: number): number[] {
  // prettier-ignore
  return (new Array<number>(n)).fill(0);
}
  • literal-default-parenthesized positive new → verified
    // Parameters with no annotation whose defaults are parenthesized literals:
// parentheses are transparent, so each default states the literal's type
// widened, as TypeScript's `isolatedDeclarations` declares it, exactly as
// written without them (`literal-default-parameters`).
export function flags(
  // prettier-ignore
  singleLine = (false),
  // prettier-ignore
  strict = (true),
): boolean {
  return singleLine && strict;
}

export function numbers(
  // prettier-ignore
  n = (3),
  // prettier-ignore
  negative = (-1),
): number {
  return n + negative;
}

export function strings(
  // prettier-ignore
  s = ("a"),
  // prettier-ignore
  t = (`b`),
): string {
  return s + t;
}

export function calls(): boolean {
  return (
    flags() &&
    numbers() === 2 &&
    strings() === "ab" &&
    flags(true, false) === false
  );
}

    // Parentheses are transparent but an optional chain is not: the reviewed

  // prettier-ignore
