State the typed array's three host steps by the note's rules and keep every view store canonical

refused

Why

The contracts of %ByteSet%, %ByteAt% and %ByteLength% (b[i] = v, b[i], b.length of a typed array) were assumed as the pass happened to read them: the exact write stated only a safe integer already in the format's range written at an index the precondition made valid, with the other indices keeping the same cells. The note *Tolerant frames* states the three steps as rules the host meets (View-Length, View-Read, View-Write; owner decision 2026-11-15: no reduction rule, soundness relative to a host meeting them). A write of 300 to a Uint8Array reads back 44, one of -1 reads back 255, one of NaN reads back 0, and a write at an index past the end changes nothing; none of this was stated. Besides, the canonical contract of a view store (the store's contract admits every replacement a write through an overlapping typed array may make) was proved for worlds that chose it, but no admitted state was required to have it, so a world whose view store had a narrower contract made the write's assumed postcondition unsatisfiable by any host.

State View-Write of every element assignment and read a written NaN as any NaN

refused

Why

Review of the previous commit: the total View-Write was required only with the exact signatures' precondition, so b[0] = 300 or b[NaN] = 1 got the frame alone from %ByteSet%'s first signature, while the note states View-Write of every numeric element assignment. And a Float64 element written a NaN was stated to hold the bits 0x7ff8000000000000, while ECMA-262 lets the host choose a NaN's bits.

/** @requires 300 <= widths.length */
export function past(widths: number[], bytes: Uint8Array): number {

Soundness
