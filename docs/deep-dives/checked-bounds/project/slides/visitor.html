A callback left out still costs the call its frame

type Visitor = (i: number) => void;
 
function walk(n: number, onItem?: Visitor): number {
  let s = 0;
  for (let i = 0; i < n; i++) {
    s += i;
    onItem?.(i);
  }
  return s;
}
 
/** @requires safeInteger(i) && 0 <= i
 *    && i < xs.length */
export function get(xs: number[], i: number): number {
  const n = walk(3);   // no visitor passed
  return xs[i]! + n;   // refused
}

  • One frame per function: walk’s frame is inferred once, for every call. An unknown callback may change any array, so the frame is stores: "any".
  • The caller pays: get is refused although walk(3) runs no callback: the call drops i < xs.length.
  • A frame on the callback’s type: with Visitor stated stores: "grow", get verifies; a public function handing its own caller’s callback to walk is then refused.
  • A run-time check: if (i >= xs.length) throw … after the call verifies. It never fires; it stands in for the proof.
  • In pretext: one such check stands before a call in a loop that also calls a line walker without its optional visitor.
