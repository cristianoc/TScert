A callback left out still costs the call its frame

type Visitor = (i: number) => void;
 
function walk(n: number, onItem?: Visitor): number {
  let s = 0;
  for (let i = 0; i < n; i++) {
    s += i;
    onItem?.(i);
  }
  return s;
}
 
/** @requires safeInteger(i) && 0 <= i
 *    && i < xs.length */
export function get(xs: number[], i: number): number {
  const n = walk(3);      // no visitor passed
  if (i >= xs.length)     // the runtime check
    throw new RangeError("index");
  return xs[i]! + n;
}

  • One frame per function: the producer infers walk’s frame once, for every call. An unknown callback may change any array, so it is stores: "any".
  • Without the check: get is refused, though walk(3) runs no callback. The diagnostics name onItem?.(i), whose frame is stores: "any", and walk(3), which drops i < xs.length.
  • A frame on Visitor: stated stores: "grow", get verifies; a public function handing its caller’s own callback to walk is refused.
  • With the check: verified. The check never fires; it stands in for the proof.
