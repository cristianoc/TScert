the target with and without the invariants, at one TScert commit · measured

A coarse frame condition costs the handle its invariant

/** @invariant this.segmentFlags.length
 *     === this.widths.length */
type PreparedLineBreakData = { … }
 
function layout(prepared: PreparedText, …) {
  const lineCount = countPreparedLines(…)
  // inside: getEngineProfile() writes a
  // module cache; frame condition value: any
  return { lineCount, … }
  // obligation: prepared meets its invariant
}

  • Measured: with the length invariants on pretext’s handle, 137 functions verify, against 144 without them: 9 lost, 2 gained.
  • Return obligation: a parameter never reassigned must meet its invariant again at every return, so its callers keep it.
  • Coarse frames: a call whose frame condition is value: any (a Map.set on a module cache, getEngineProfile, an onLine callback) may rewrite any field, so the facts are lost and the return obligation fails.
  • Defaults: a parameter with a default, start = TEXT_START_CURSOR, gets no precondition, so its invariant is never assumed.
  • What closes it: frame conditions that separate a module cache from the arguments, and preconditions on defaulted parameters (proposed). The invariant is the right specification; the frame is too coarse.
