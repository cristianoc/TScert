Growth keeps the lower bounds of lengths

function add(xs: number[]): Modifies<
    { values: "any"; stores: "grow" }, void> {
  xs.push(1);
}
 
/** @requires safeInteger(i) && 0 <= i
 *    && i < xs.length */
export function get(xs: number[], i: number): number {
  add(xs);
  return xs[i]!;      // verified
}
 
export function last(xs: number[], ys: number[]): number {
  if (xs.length > ys.length) return 0;
  add(xs);
  const n = xs.length;
  if (n === 0) return 0;
  return ys[n - 1]!;  // refused
}

  • Growth: stores: "grow" states that every array keeps each element present and gets no shorter, within the maximum length 2³² − 1.
  • Lower bound: a fact whose length terms all have coefficients ≤ 0, such as i < xs.length, read i − xs.length ≤ −1. Growth keeps every such fact whose other terms it keeps.
  • Where it applies: a call stated stores: "grow"; push; an element write out[j] = v at any index, which may lengthen any array, xs among them.
  • Upper bound: dropped: add(xs) may lengthen xs, so xs.length <= ys.length is lost and last is refused; under Node last([], []) returns undefined.
  • Natives: each native contract stated at store: grow (push, unshift, sort, a typed array’s fill, set, copyWithin) also states that its arrays get no shorter: trusted, argued from ECMA-262.
