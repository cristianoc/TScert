Type invariants

an opaque-type regression example, after pretext’s handle · the boundary rules proved

Type invariants become preconditions and postconditions

/** @invariant this.segmentFlags.length
 *     === this.widths.length
 *  @representation PreparedLineBreakData */
export type PreparedText = {
  readonly [preparedTextBrand]: true
}

  • Representation invariant: PreparedText is opaque; @representation names its underlying record. The invariant equates two array lengths.
  • Precondition: for a parameter without a default argument, callers establish the invariant and the body assumes it.
  • Postcondition: every normal return establishes result invariants and restores those of parameters never reassigned.
  • Casts: a cast checks the representation type; the invariant needs proof at a call or return.
  • Preservation: across calls, keeping the equality needs a frame condition that protects the field references and the lengths.
