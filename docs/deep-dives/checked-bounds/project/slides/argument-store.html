A frame naming one array keeps the lengths of the others

type Runs = { /** @stable */
  readonly openBrackets: number[] };
 
function readRuns(runs: Runs): Modifies<
    { values: "any";
      "runs.openBrackets[*]": "any" }, void> {
  runs.openBrackets.splice(0, 1);
}
 
export function measure(flags: number[]): number {
  const runs: Runs = { openBrackets: [] };
  let sum = 0;
  for (let i = 0; i < flags.length; i++) {
    readRuns(runs); sum += flags[i]!; }
  return sum;
}

  • Stated frame: Modifies<P, T>, read by TypeScript as T. P lets readRuns change any value and, through the region "runs.openBrackets[*]", the array runs.openBrackets holds at the call; stores left out, every other array is kept. The checker certifies the body against P.
  • @stable: a readonly field holding what its object literal put there for the record’s life: the region names one array across every call.
  • Separation: the literal’s [] is a new array, so it is not flags: the loop keeps i < flags.length across each call, and flags[i]! is in bounds. A record from a caller needs the precondition flags !== runs.openBrackets: distinct arrays. Of typed arrays it is refused; two views may share a buffer.
  • Alias: a caller passing one array as both is refused at that precondition; under Node that call returns NaN (invalid-stated-alias).
  • In pretext: a helper splices a bracket stack held by a record that its caller builds before a loop over other arrays: this shape.
