What expr’s statement needs

D-numbers: decisions of the design document

What expr’s statement rests on

  • forEachChild, TypeScript’s method calling a visitor function on each child of a syntax node, which functions expr reaches call: its contract has one signature per footprint of the table on “The footprint F” (six: value keep or any, with store keep, grow or any), taking visitors within that footprint and making the call within it, as map’s does (“Built-ins state footprints in their contracts”) (design decision D7; that it runs no code of the program but its visitors is reviewed by hand).
  • TypeScript’s type checker. The parser reads type annotations through a scope, an object of type TermScope whose function members resolve names and types and state value: any, store: grow. TScert’s reader of declaration files (.d.ts files) makes such scopes, which query TypeScript’s own type checker, distinct from TScert’s checker. Those queries are read as an audited contract, reviewed by hand: value: any, store: grow on normal return, except six that may receive an object of the program: sending it to TypeScript’s process converts it to JSON, which runs its toJSON method and getters, so these six state no effect, and a body calling one has no certified bound on its effect (design decision D8 (a)).
  • The shift calls. shift on an array the call did not allocate allows any change to stores. By design decision D5, an exception to the rule that TScert’s source is not rewritten to fit the verifier (approved 2026-10-23, WORK.md), Gate’s four shifts on its two stacks of scopes (in enterTypeParams and leaveTypeParams) are field writes, such as this.typeParamScopes = this.typeParamScopes.slice(1), unobservable since no other code holds either array; the two in closures of protocolForOf (the parser of for-of over an iterable) are reads at counters.
  • A checker rule for a method call with names or literals as arguments on a value of several shapes, such as node.getStart(file) on a Node: TScert reads and calls the method in one step, which no rule bounding a footprint admits, so a body making it has no certified bound on its effect (design document §10). Gate’s own methods make such calls (span calls node.getStart). The design document adds the rule if a measured slice is refused at such a call.
  • Statements on everything expr reaches, each certified where a verifying slice includes it, callers otherwise verified relative to it: 61 of the 183 functions expr and the parser’s TermScope reach are certified (docs/drafts/method-effects-inventory.md, 2026-10-24).
