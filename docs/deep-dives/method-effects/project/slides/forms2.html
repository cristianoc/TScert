A field holding a module function, and a throw as an exit

A field holding a module function

function scaled(this: Scale, n: number): Modifies<{}, number> {
  return n * this.factor; }
class Scale { factor: number = 2; scaled: typeof scaled = scaled; }

A module function is a top-level function of a module; this: Scale is TypeScript’s this-parameter. The field’s type is the function’s own, statement included, so a call s.scaled(x), for s: Scale, relies on it; a function written into the field is checked against that type. (Runner’s helper field, on “Examples refused”, has the type of a function stating nothing.) TScert’s own parser holds many functions this way (later slides).

A throw as a possible exit

positive(n: number): Modifies<{ onThrow: true }, number> {
  if (n < 0) throw new Error("negative"); return n; }
// c: Check, the class of positive; xs: number[]
const r: number[] = xs.map((x) => { try { return c.positive(x); } catch { return 0; } });

The callback returns normally from its catch block, so what positive changes when it throws counts toward the callback’s return: with onThrow, nothing, and map’s result is hole-free. Without onThrow the throw is unbounded (refused variant: invalid-method-effect-stated-throw-caught.ts).
