Three statements that fail their check

A body that breaks its statement. bump states that nothing changes, but pops the array it is given (invalid-method-effect-method.ts).

class Bump { bump(xs: number[], x: number): Modifies<{}, number> {
  xs.pop(); return x; } }

An unstated call inside. run states that nothing changes and calls this.helper. Though helper changes nothing, a Runner may hold there any function of the field’s type, which states no effect (“Contract closure”, later; invalid-method-effect-unstated-dependency.ts).

function helper(xs: number[], x: number): number { return x; }
class Runner { helper: typeof helper = helper;
  run(xs: number[], x: number): Modifies<{}, number> {
    return this.helper(xs, x); } }

An override. Drain.take overrides Base.take and pops; the override need not repeat Modifies: its body is checked against Base.take’s statement (invalid-method-effect-override.ts).

class Base { take(xs: number[], x: number): Modifies<{}, number> { return x; } }
class Drain extends Base { take(xs: number[], x: number): number { xs.pop(); return x; } }
