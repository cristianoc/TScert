Words used in this deck

How TScert works, in three cards

Verified, refused

TScert verifies a function when it proves it safe: every value the function reads, writes or returns has its declared type. Otherwise it refuses the function, naming the first place it could not prove.

Statement

An effect is what a call may change; in this deck a statement is an effect a function declares in its result type (“What you write”), bounded by a footprint (“The footprint F”). A statement of TypeScript code, such as an if, is called a TypeScript statement.

Producer and checker

TScert’s parser, its front end, reads the TypeScript source; it is trusted, and reviewed by hand. From the parser’s output an untrusted producer proposes type claims (the types it asserts each value has) and effects, also of code that states none, and an untrusted search looks for their proofs. Untrusted: their mistakes cannot make TScert accept, since a checker, written and proved in Lean, a proof assistant, accepts only what it checks.
