The effect goes in the result type, as Modifies<P, T>

note(n: number): Modifies<{ values: "any"; stores: "grow" }, number> {
  this.entries.push(n);
  return n + 1;
}

  • Modifies needs no import, only its declaration file listed in the project’s tsconfig.json: it is a global type alias in tools/resolvable.d.ts (tools/, the directory of TScert’s TypeScript front end). To TypeScript, Modifies<P, T> is just T, so the code compiles and runs unchanged. TScert recognises Modifies by that declaration, or an identical copy of its file: another type called Modifies is an ordinary type.
  • To TScert it is a statement about the call: on a normal return, the call changes memory that existed before it at most as P, the frame, allows. With onThrow: true in P, this holds also when the call throws; without it, the statement says nothing about a throw.
  • P has the class keys values (written value below) and stores (store), whose settings the next slide lists, an omitted key keep, and optionally onThrow: true; in prose this deck writes the settings without quotes. note states store: grow (it keeps arrays’ hole-free prefixes hole-free, next slide, as its push onto entries, a number[] field of its class Log, three slides on, does) and value: any, because push’s contract states value: any (two slides on).
  • TScert checks the function’s own body against the statement in a run that includes its definition, whether or not any code calls it; the statement is certified when that run verifies. Callers rely on the statement.
