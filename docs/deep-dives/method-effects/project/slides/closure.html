pattern’s map needs the expression parser to state its effect

const props: PatternPropAst[] = node.elements.filter((el) => !el.dotDotDotToken).map((el) => {
  … return { …, target: gate.pattern(el.name, names),
    default_: el.initializer ? gate.expr(el.initializer) : null };
});

  • What it is: pattern parses a destructuring pattern, such as { a, b = f() }. For an object pattern it maps the elements other than a rest ...r (whose dotDotDotToken is set) to a PatternPropAst each, the parsed form of one property. filter’s callback calls nothing. The map’s callback (besides gate.fail, typed never, and ts.isIdentifier, not shown), whose default_ is the property’s default expression parsed, calls gate.pattern (pattern itself, on the element’s name; names collects the names bound so far) and gate.expr, the expression parser, on its default: both module functions in Gate’s fields, so the calls rely on the statements the fields’ types carry (“A field holding a module function”).
  • Reach: in the census run at commit 6a3a864, 21 slices stop first at this map: pattern’s, forOfPattern’s (the parser of a pattern in for (const { a } of xs)), and 19 others whose slice includes pattern.
  • Cost: to keep the map’s result hole-free, pattern and expr must state an effect, and so must what they reach through Gate’s fields. pattern calls itself through the field gate.pattern, whose type carries pattern’s own statement: the call relies on it by the rule for calls through a field (“A field holding a module function”), which is not circular, since the function written into the field is checked against its type there; recursion through a field has no test case of its own. By contract closure, expr can state one only if everything it reaches through Gate’s fields and methods does: 166 functions, by an untrusted syntactic scan (docs/drafts/method-effects.md).
