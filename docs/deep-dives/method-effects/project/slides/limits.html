Forms that cannot carry a statement

RefusedWhy
async functionsthe body may run on after an await, once the call has returned, and a throw in it rejects the returned Promise instead of leaving the call, so no statement covers the body
overloaded functionsthe body is checked once, at one signature, so a statement on one overload would not cover the others
generic arrows, function expressions and methods, any method of a generic classeach is checked at bounds (upper types) the producer chooses for its type parameters, which may not cover every type argument a caller uses
constructors and construct signaturesthe effect of constructing an object belongs to its class’s whole construction (field initialisers and constructor body), so no constructor carries a statement
declaration files and packagestheir code lies outside the checked program, and no run of TScert checks it
getters and settersTScert refuses every accessor definition, with or without a statement
Within as the type of a parameter, a field or an array element itself (x: Within<…>)a statement is the effect of the signature whose result it is
F given as a named type aliasTScert reads F only from the literal written inside Within

A generic function declaration may carry a statement: its annotated parameters are its inputs, so it is certified over its whole written signature. Its callers ignore the statement, so a map callback calling one gets map’s signature with holes: the generic declaration’s instances carry no footprint at that call.
