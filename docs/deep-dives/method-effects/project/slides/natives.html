The footprint F, continued

Built-ins state footprints in their contracts

  • push’s contract is value: any, store: grow. store: grow is proved in Lean from push’s steps in the ECMAScript specification (theorem Arr.push_grow, lean/Verification/Semantics/FootprintNatives.lean). The part reviewed by hand says that push changes nothing but its array’s store and its elements’ contents. It allows changes to the contents of elements that existed before the call, which are ordinary locations, so it states value: any; by the ECMAScript steps, push itself writes only indices past the old length, and TScert states no tighter contract for it.
  • map’s contract has five signatures: four for a hole-free array and a callback within one of the footprints (value, store) {keep, keep}, {any, keep}, {keep, grow} or {any, grow}, each with a hole-free result, proved (map_rely, FootprintNatives.lean) assuming map tests presence only between callbacks (reviewed by hand), since map reads the length once and grow keeps the indices below it, and each giving the whole map call the callback’s footprint, so a caller keeps what that footprint preserves; and one for any array and callback, whose result may have holes (a callback with store: any may remove elements). Any of the four that the callback’s footprint is within gives a hole-free result; that footprint is found from the callback’s code and its callees’ statements and contracts.
  • value: any, store: any is refused as a statement: it states nothing.
