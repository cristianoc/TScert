The options argument of Error

class Failure extends Error { constructor(message: string) { super(message, {}); } }
export function use(): Error { return new Error("failed", { cause: "reason" }); }

  • Why it is not proven: TScert's contract for Error states its message argument alone. Its second argument, an options object, is not stated: by ECMAScript's description of the Error constructor (InstallErrorCause, cited), the host checks whether it has a property cause and, if so, reads it and copies it to the new error; the check and the read may run code (a getter, a proxy). The gate refuses both forms (tools/fragment-classes.mts:754; tools/declaration-graph.mts, “is read with at most 1 argument”).
  • What proving it needs: the contract of new Error(message, options) and super(message, options): options an object whose cause, when present, is copied to the error's own field cause, admitted where the check and the read run no code, such as an object literal of plain fields; the rule goes into SOURCE-ELABORATION.md, “A class extending Error”.
  • What it would trust: trust change: the host follows ECMAScript's description of the Error constructor.
