A callback parameter whose context is a library type

export function bound(scopes: readonly ReadonlySet<string>[], name: string): boolean {

  return scopes.some((scope) => scope.has(name));

}

  • Why it is not proven: an unannotated callback parameter takes the type TypeScript gives it from its context only when that type is built from primitives, literals, unions, intersections, arrays, tuples, type parameters and declarations by name; a library interface such as ReadonlySet<string>, Map<string, string> or PromiseLike is refused. lowerFile (692 statements) meets it.
  • What proving it needs: read a context type that names a library interface as an annotation naming it would be read, with the same refusals where that reading has none.
  • What it would trust: nothing new: an annotation of the same type already rests on the same library declarations.
