How TScert works, in three cards

Verified, refused

TScert verifies a function when it proves it safe: every value it reads, writes or returns has its declared type. Otherwise it refuses it, naming a location and a reason. The first stage, the gate, reads the TypeScript source and refuses what lies outside the language TScert admits; the later stages search for the proof and check it.

Contract

TScert's reviewed description of code it does not check itself: a function of JavaScript's standard library, of Node, or of TypeScript's compiler interface, each listed with its exact declaration and audited by hand. A contract is an assumption the result rests on: adding one widens what TScert trusts. A library global with no contract is refused; a function imported from a library with no contract is read through its declaration's written types.

Case, gap case

A case is a small TypeScript file with the outcome TScert must give it, checked by the test suite (make suite). A gap case is one TScert refuses for want of a rule or a contract, though the program is safe: it turns into a verified case once the missing piece is added.
