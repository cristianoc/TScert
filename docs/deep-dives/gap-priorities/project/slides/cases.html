Part 1 · from a failure to a case

Each heavy cause has a small case example, where one is found

// the source that the census site at fragment-classes.mts l.713 (slide “Cause 8”) reduces to

type E = { readonly k: "id"; readonly name: string }

  | { readonly k: "alloc"; readonly fields: readonly { name: string; e: E }[]; readonly proto?: E };

export function link(name: string, proto: E | null): E {

  const l: E = { k: "alloc", fields: [{ name: "message", e: { k: "id", name } }], ...(proto ? { proto } : {}) };

  return l;   // refused at l's annotation: the literal's k is claimed a string

}

  • A case example: is the smallest source with the cause's refusal; one made from a census names in its header the census functions it stands for. The test suite (make suite) checks its expected outcome on every run.
  • A gap case: is a safe program TScert refuses for want of a rule or a contract. A negative case is a refusal that is right: the program could produce a wrong value.
  • This census: seven of the ten heaviest causes, numbered on slide “The ten causes”, have no case. The source above, not yet a case of the suite, reproduces cause 8, and without its spread it verifies; a four-line source reproduces cause 5 (measured). For causes 1 and 2 no small source is found yet. Writing these cases is the next step.
