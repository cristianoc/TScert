Priority favors reasons blocking many small functions

  • Each function contributes: 10 / (10 + its statement count). A function with 10 statements contributes 0.5; one with 90 contributes 0.1. Smaller functions tend to have fewer further refusals behind their first.
  • A group’s weight: the sum of those contributions. Groups appear in descending weight, rounded to three decimals in the tables. The statement and function columns give the code each group blocks. Weight is a priority rule; future gains are unmeasured.
  • One construct per group: a generic failed-search message is split by its refused expression and the functions reaching it. Field-key conversion and numeric-claim conversion are separate groups, with different input contracts. Shared syntax identifies an observed construct; it does not prove a common defect.
  • Read the sites: all 257 refusal details agree with the record, and every refused slice matches its recorded source hash. The leading twenty groups’ source contexts and case comparisons are in work/round/ranking.md and site-contexts.md in session storage.
