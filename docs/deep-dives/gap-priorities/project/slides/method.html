How the nine were chosen

Rank the gate's reasons for refusal by the code they block, then take the cases that show them

  • The census: each top-level function of the front end (the folder tools/) is copied into a file of its own and run through TScert. In the census of commit 963ffa4 (2026-10-24), 178 of 490 functions are verified and 312 refused (measured).
  • Past the first refusal: a refused function stops at its first reason. A separate diagnostic tool rewrites the copy crudely at each refusal and runs it again, so that later reasons show up too; its run finished for 210 of the 312 functions (measured). Every reason met, first or later, is kept.
  • Aspects: the reasons are grouped by cause (an aspect), leaving out causes fixed on main since. Only the gate's reasons are grouped: those of the later stages vary from function to function. An aspect's weight is the number of statements (an if, a return, an assignment …) in the functions it blocks, and the number of those functions.
  • Cases: every aspect blocking more than 1,000 statements or more than 40 functions; for each, the existing gap cases whose expected refusal is that aspect. Seven aspects have cases; two have none (slide “What the ranking found with no case”). No case was written for this deck.
  • One caveat: one function, collectDeclarations, has 2,334 statements and meets five of the seven aspects, so it dominates their statement weight; the function counts do not have that bias.
