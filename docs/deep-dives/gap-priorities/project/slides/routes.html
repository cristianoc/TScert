Part 2 · how a refusal is decided

Eight routes, the first that works at acceptable cost

RouteWhen it applies
1. Supporta rule or contract admits the construct: it has useful reach in the census and a proportionate implementation
2. A runtime checkan executable check establishes the whole property, also after later writes; checking a value's shape says nothing of what code writes
3. A repairthe refusal exposes a defect in TScert's code, which changes
4. Avoidancesupport is costly, the construct rare, and a rewrite is observationally equivalent; the construct stays refused
5. A host boundarya necessary operation on an external package moves to the smallest module, whose functions take only values that package makes
6. A trusted unitthe project's owner approves exempting a narrow unit of TScert's code from checking, reported with its contract; never a fallback
7. A proofa proof in Lean, the proof assistant TScert's checker is proved in, where the model of JavaScript it needs exists or has wider value
8. The refusal staysno route works at acceptable cost; the census reports it
