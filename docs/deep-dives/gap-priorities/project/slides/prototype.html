Object.getPrototypeOf, confined to a host boundary

The use

The compiler channel (compiler-channel.mts), the front end's link to TypeScript's compiler process, checks and wraps the six methods by which the TypeScript package's private client sends a request, on the client's class prototype.

Why no other route

An entry (o) => object | null is unsound: Array.isArray narrows getPrototypeOf([]) to an array whose writes reach every array; instanceof narrows a prototype to an instance without its fields. No rewrite avoids it: reading a method through the client itself may run a getter, code TScert does not see.

What it guarantees

The wrapper sends each request and returns its answer, or a repeated query's earlier one (a stated conjecture). The caller's callback only runs code around that call (send, once): it cannot replace an answer or hide a failure.
