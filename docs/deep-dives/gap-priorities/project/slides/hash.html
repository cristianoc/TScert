Node's createHash

import { createHash } from "node:crypto";

export function use(s: string): string { return createHash("sha256").update(s).digest("hex"); }

  • Why it is not proven: createHash has no contract, so the gate reads Node's declaration of it and every type that declaration names, each through its written annotations. Its options type HashOptions extends the stream type TransformOptions, where TypeScript gives one member a type it builds itself, with no written declaration behind it; no annotation states that member's type, so the gate refuses. The functions are many and small.
  • What proving it needs: contract entries for createHash and for the update and digest methods of its result (entries for a returned value's methods are a new form), at the arguments tools/ uses (a string algorithm, string or byte data, as Uint8Array or Buffer, the hex encoding; Buffer is aspect 7), after an audit of Node's hash code, which is to establish, among others, what an unknown algorithm and a second digest do. A function with a contract is read through it, and its declaration's types are not read.
  • What it would trust: trust change: three entries about Node's crypto module.
