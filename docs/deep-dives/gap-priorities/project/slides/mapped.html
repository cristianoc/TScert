gap written-partial-argument-refused

A mapped type whose field type depends on its key

type G<T, K extends keyof T> = K;

export function f(x: keyof { z: G<Partial<{ 0: number }>, 0> }): "z" {

  return x;

}

  • Why it is not proven: a mapped type {[P in K]: V} gives every key P the same field type V, and TScert reads it only when V does not mention P. Partial, Readonly and Pick write T[P], the type of the source's own field P, so the gate refuses them wherever they are written (tools/type-term.mts:546). In tools/, Readonly meets 45 of the 51 functions, Partial 4 and Pick 3 (measured).
  • What proving it needs: one reading rule more: when the keys are a known list of literal keys, each field k gets V with P replaced by k, T[k] reads the field k of T, and the modifiers ? and readonly apply as written. Readonly<{ a: string }> is then { readonly a: string }. A mapped type over a type parameter with no known keys stays refused.
  • What it would trust: nothing: it is a reading of a type annotation, not a contract.
